# 회귀 테스트

Windows와 .NET 8 SDK에서 저장소 루트의 `./test.ps1`을 실행합니다.

```powershell
.\test.ps1
```

게임 설치나 실제 원본 로그 없이 실행됩니다. 최초 실행 시 NuGet 패키지를 복원합니다.
직접 실행하려면 다음 명령을 사용합니다.

```powershell
dotnet test tests/BossMonitor.Tests/BossMonitor.Tests.csproj -c Release
```

## 테스트 데이터

- `tests/fixtures/real-session`: 실제 게임 로그에서 파서에 필요한 507개 이벤트를 추린 익명화 자료입니다. 총 7개의 레이드 상태(로그 경계 때문에 생긴 맵 미확인 상태 포함)를 복원합니다.
- `tests/fixtures/infected-tagilla-plan`: 1.3.0 공장 레이드의 감염된 타길라 판정(`ShallSpawn:False BossChance:6`)을 추린 최소 자료입니다. 원본 시각과 판정은 유지하고 레이드 ID와 애플리케이션 메시지의 부가 필드를 정리했습니다. 실제 활성화·사망은 아직 확보하지 못했으므로 가상 로그 테스트로 검증합니다.
- `expected.json`: 보관한 **원본 로그**를 재생해 얻은 기대 상태입니다. 익명화 자료를 재생한 결과와 일치하는지 확인한 뒤 저장했습니다. 보스, PMC 난이도, 레이더, Scav, 최초 구역·좌표, 사망 좌표, 웨이브 수와 종료 상태 등을 비교합니다.
- `ReaderRegressionTests.cs`: 실제 보관 자료에 없는 감염자·Impossible PMC·로그 조각·ID 재사용·줄 간격 경계·맵 이동 등의 사례를 가상 로그로 만듭니다. 실제 플레이 기록과 구분됩니다.
- `UiRegressionTests.cs`: 한국어·영어·중국어에서 실제 `MainWindow.Render`를 실행해 로그·레이더 영역 유지, Labs의 Scav/감염자 숨김, Impossible 생존 수, 종료 문구 및 상태 변경 시 다시 그리기를 확인합니다. 이벤트 영역이 보스 아래에 배치되고 오른쪽 일반 AI 영역과 분리되는지, 상단 오른쪽 킬 수가 레이드 ID 없이도 갱신되는지도 검증합니다.
- `WindowPlacementTests.cs`: 양수·음수 좌표에 놓인 보조 모니터에서 창 크기가 커지는 경우와, 화면 밖 창을 다시 여는 경우를 가상 좌표로 확인합니다.

WPF 테스트는 STA 스레드에서 실행합니다. 트레이·타이머·사용자 설정을 초기화하는 창 생성자는 우회하고, 렌더링에 필요한 WPF 컨트롤만 주입합니다. 실제 창을 띄우거나 게임 설정을 변경하지 않습니다. 실제 화면 배치나 게임 실행 중 동작을 직접 확인하는 테스트는 아닙니다. 언어 환경 변수가 프로세스 전체에 적용되므로 테스트 병렬 실행은 끕니다.

창 동작을 수동으로 확인할 때는 배율이 다른 두 모니터에서 창을 보조 모니터 하단에 두고 설정을 여닫습니다. 이어서 최대화·최소화와 트레이 숨김 상태에서 트레이 메뉴 및 바로가기로 다시 열어 같은 모니터에 표시되고 키보드 입력을 받는지 확인합니다. 트레이로 숨긴 뒤 보조 모니터를 분리하는 경우에는 남은 화면에서 창을 열 수 있는지 확인합니다.

## 익명화 범위와 줄 간격

프로필 ID와 레이드 ID는 같은 원본 값에 항상 같은 가상 ID를 부여했습니다. 닉네임은 `FixturePlayer`, `FixtureEnemy`, `FixtureBot`으로 바꿨으며, 게임 폴더 경로·네트워크 요청 본문 등 불필요한 원문은 포함하지 않았습니다. 게임 버전, 이벤트 시각, 역할, 좌표와 ID 연결 관계는 유지했습니다. 원문 보존이 필요한 PMC 프로필/생성 행과 활성화 행은 공백 형식도 유지했습니다.

파일 사이의 시각 관계와 각 파일의 이벤트 순서는 그대로입니다. 빈 줄은 빠진 원본 행의 자리이며, 65줄을 넘는 공백 구간만 65줄로 줄였습니다. 파서의 사망·난이도 연결 조건인 **같은 파일, 최대 64줄 간격**의 참/거짓이 바뀌지 않도록 한 것입니다. 빈 줄을 제거하면 안 됩니다.

기대 파일에서는 절대 경로를 포함하는 `Key`, 익명화한 `RaidId`와 `Profile`을 제외합니다. 나머지 상태 필드는 모두 비교하며, 가상 ID 연결과 난이도·사망 연결은 별도 경계 테스트로 확인합니다. 제품 로직이 달라져 실패한다면 결과를 검토하고 기대값을 변경해야 합니다. 현재 출력으로 자동 덮어쓰지 않습니다.

## 로컬 원본 로그

검증에 썼던 2026-10-26 21:10:53, 2026-10-27 21:46:40 세션 전체를 `work/test-logs/Logs/`에 복사했습니다. 복사 직후 모든 파일의 SHA-256이 원본과 일치함을 확인했습니다. `work/`는 기존 `.gitignore`에 포함되어 원본과 로컬 출처 기록은 커밋되지 않습니다.

이 원본도 함께 검증하려면 다음 명령을 사용합니다.

```powershell
.\test.ps1 -IncludePrivateLogs
```

최신 보관 세션을 재생해 저장소의 익명화 기대 상태와 비교합니다. 기본 실행에서는 이 선택 테스트 하나가 건너뛰어지며, 원본이 없으면 위 옵션은 오류를 냅니다. 원본이 다른 세션으로 바뀌면 기대 상태와 비교가 실패하도록 되어 있습니다.

결과 TRX 파일은 무시되는 `work/test-results/`에 저장됩니다. 테스트용 로그 변경은 임시 디렉터리에서 수행하고 종료 시 정리하며, 원본 아카이브는 읽기만 합니다.
